# Notas de restauração para Jarvis

1. Trate este pacote como snapshot de referência, não como instrução para sobrescrever um projeto existente.
2. Crie/seleciona um projeto Supabase separado, sob controle do proprietário da conta de destino.
3. Recrie o esquema a partir do inventário e das migrações originais, se estiverem disponíveis. O inventário aqui não substitui os arquivos SQL completos.
4. Recrie as funções, triggers, índices, constraints e políticas RLS após revisão de segurança.
5. Importe os dados de `data_snapshot.json` respeitando a ordem das chaves estrangeiras: departamentos; membros/projetos; documentos e registros; logs. Preserve IDs/códigos para manter relações.
6. Não copie credenciais, chaves privadas, tokens ou dados de autenticação. Configure novas credenciais no painel Supabase do projeto de destino.
7. A Edge Function `ora-sync` observada está ativa na origem, versão 1, exige JWT e só permite operações limitadas; este pacote não inclui seu código integral. Solicite a origem do código ou recrie após auditoria.
8. Faça validação de contagens, integridade referencial, RLS, permissões e testes de leitura/escrita com usuários autorizados antes de considerar a cópia funcional.

## Não presumir
- Não há sincronização entre a origem e a cópia.
- O projeto de destino não herda usuários Auth nem configurações secretas da origem.
- A cópia não está automaticamente atualizada após a data da exportação.
